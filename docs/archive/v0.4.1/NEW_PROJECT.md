# trio-sync — запуск на новом проекте

_Отдай этот файл Cowork или Claude Code на новом проекте — вставь в чат, прикрепи, или просто попроси «прочитай и настрой». Файл самодостаточен: работает, даже если скилл/плагин trio-sync ещё не установлен в этой конкретной сессии — все нужные шаблоны и правила продублированы прямо здесь. Канонический источник, который поддерживается активно — `plugin/skills/trio-sync/SKILL.md` в `github.com/Myrshefor/.trio`; если этот файл и тот скилл когда-нибудь разойдутся, прав скилл._

---

## Кто ты и что делать

Если ты — Cowork или Claude Code, и пользователь (chyits) дал тебе этот файл — значит, он хочет включить **trio-sync** на текущем проекте: общий файловый протокол хендоффа контекста между обычным чатом Claude (Chat), Claude Code и Cowork, чтобы все три поверхности видели, что уже сделано, решено, спрошено или отвечено — без пересказа контекста заново каждый раз. Полное описание — `docs/architecture.md` в исходном репозитории, если он у тебя под рукой; для запуска он не обязателен, этого файла достаточно.

### Шаг 0 — проверь, установлен ли у тебя уже сам скилл/плагин trio-sync

- **Cowork:** посмотри список активных скиллов сессии. Если `trio-sync` там есть — дальше следуй его инструкциям напрямую (он новее и подробнее этого файла), а этот файл используй только как чеклист вопросов пользователю ниже.
- **Claude Code:** `/plugin list`. Если `trio-sync` установлен — так же, действуй по нему.
- **Если не установлен нигде** — не блокируйся на этом. Либо (а) попроси пользователя прислать `.plugin`/marketplace-zip файл, либо укажи на `README.md` репозитория `github.com/Myrshefor/.trio` («Install in Cowork» / «Install in Claude Code»), либо (б) просто выполни шаги ниже вручную — они самодостаточны и не требуют установленного скилла.

## Шаг 1 — прежде чем создавать что-либо, спроси пользователя

Не угадывай эти ответы — они меняют, что именно будет создано. Задай одним сообщением, не растягивай на серию вопросов:

1. **Как называется проект?** (пойдёт в заголовки `STATUS.md` и остальных файлов)
2. **Где физически лежит проект?**
   - Code: рабочая директория обычно и так ясна — просто подтверди путь.
   - Cowork: сначала попробуй найти сам, не проси сразу вводить путь текстом. Проверь уже подключённые папки; если проекта там нет — пройдись по вероятным родительским (Desktop, Documents, домашняя папка, или соседняя с уже подключённой) в поисках папки с названием проекта из вопроса 1 — листинг родителя, к которому нет доступа, всё равно покажет имена вложенных папок. Как только нашёл путь (или сузил до одного явного кандидата) — запроси доступ именно к нему, это один клик подтверждения для пользователя. Проси ввести путь вручную только если самостоятельный поиск ничего не дал. Подробности — `SKILL.md` → «Cowork: finding a project folder via device-bridge».
3. **Уже есть git-репозиторий для этого проекта, или его нужно создать?** Если есть — локальный он или уже на GitHub, и публичный или приватный. Если нет — нужен ли он вообще прямо сейчас (trio-sync работает и без git; git нужен только для механизма `CHAT_LINKS.md` на Шаге 3).
4. **Будет ли `.trio/` в публичном GitHub-репозитории?** Отдельный вопрос от предыдущего — определяет, нужен ли `CHAT_LINKS.md`. Если да — узнай ссылку на репозиторий и ветку (обычно `main`), либо предложи создать репозиторий на этом же шаге.
5. **Есть ли для этого проекта отдельный Claude Project на claude.ai, внутри которого пользователь общается с Chat?** Если да — какой именно (по названию), чтобы писать туда зеркала. Если пока нет — просто зафиксируй как открытый пункт, не блокируй остальное.

## Шаг 2 — создай `.trio/` с пятью файлами протокола

В корне **проекта пользователя** (не там, где лежит сам trio-sync) создай папку `.trio/` с этими файлами. Подставь реальное название проекта и текущую дату/время.

`.trio/STATUS.md`:
```markdown
# <Название проекта> — Trio Status
_Living snapshot, not a history — see LEDGER.md for that. Last updated: <дата время> by <Chat|Code|Cowork>._

## Roles
- **Chat** — thinking partner, sounding board, sanity-checker
- **Code** — hands-on implementer
- **Cowork** — lead strategist, evaluates progress and plans ahead

## Current focus
_(над чем работаем прямо сейчас)_

## Recent decisions
_(none yet)_

## Open questions
_(none yet)_

## Next actions
_(none yet)_
```

`.trio/LEDGER.md`:
```markdown
# <Название проекта> — Trio Ledger
_Newest entry at the top. Keep entries short — a few lines, not a transcript. See DIALOGUE.md for the verbatim exchange._
```

`.trio/TO_CODE.md`:
```markdown
# <Название проекта> — Open asks for Code
_Cowork/Chat write here; Code reads and clears. Newest at the top. Empty = nothing outstanding._
```

`.trio/FROM_CODE.md`:
```markdown
# <Название проекта> — Open answers from Code
_Code writes here; Cowork/Chat read and clear. Newest at the top. Empty = nothing outstanding._
```

`.trio/DIALOGUE.md`:
```markdown
# <Название проекта> — Trio Dialogue (verbatim, never trimmed)
_Full text of everything exchanged through TO_CODE.md / FROM_CODE.md, newest first. This file is only ever appended to. It is cleared only if the user explicitly asks._
```

## Шаг 3 — видимость для Chat через публичный GitHub (только если применимо)

Если на Шаге 1 выяснилось, что репозиторий публичный (или будет создан публичным):

1. Сгенерируй `.trio/CHAT_LINKS.md` — по одной строке на файл, формат `<repo_url>/blob/<branch>/<путь>/<файл>`, на все пять файлов протокола плюс любые доп. доки проекта, если есть. Пример на самом trio-sync — файл `CHAT_LINKS.md` в `github.com/Myrshefor/.trio`.
2. Если к текущей сессии Cowork подключён Claude Project (из ответа на вопрос 5 Шага 1) — запиши `CHAT_LINKS.md` туда напрямую (`claude/trio-chat-links.md`) через инструмент Projects. Пользователю ничего вручную загружать не нужно.
3. Если Project не подключён к сессии — отдай содержимое пользователю и попроси вставить в Project Knowledge вручную.
4. Если репозитория ещё нет — зафиксируй это как открытый пункт в `.trio/STATUS.md` («видимость Chat ограничена ручной вставкой + зеркалом Cowork»), не блокируй остальную настройку.

Если репозиторий приватный или его вообще нет — пропусти этот шаг целиком, протокол работает и без него, только через зеркалирование в Project (Шаг 4).

## Шаг 4 — зеркало в Claude Project (только если применимо)

Если пользователь назвал Project на Шаге 1 (вопрос 5) и он подключён к текущей сессии Cowork — напиши туда `claude/trio-status-snapshot.md` (снимок `.trio/STATUS.md`). `trio-from-code-snapshot.md` и `trio-dialogue-mirror.md` создавать сейчас не нужно — появятся сами по мере первых реальных обменов через `TO_CODE.md`/`FROM_CODE.md`.

Это шаг только для Cowork — у Code и Chat нет инструмента Projects.

---

## Шаг 5 — подтверди пользователю простым языком

Коротко расскажи, что создано и где, и напомни: это заработает на всех трёх поверхностях, только если trio-sync установлен/включён на каждой из них (см. Шаг 0) — установка отдельная для Cowork и для Claude Code, разово, не за проект. Дай пользователю короткую памятку, как проверить, что всё видно:

- В Cowork/Code на этом проекте — спросить «какой статус», должен прочитать `.trio/STATUS.md`.
- В Chat внутри нужного Claude Project (если настроен) — спросить про текущий фокус проекта, должен взять из зеркала `claude/trio-status-snapshot.md`.

Полная таблица фраз-триггеров на каждый день (как попросить что-то передать Code, как узнать статус, и т.д.) — `plugin/README.md` в `github.com/Myrshefor/.trio`, раздел «Quick trigger phrases». Если под рукой не окажется — вот минимум, который работает всегда:

| Фраза | Что происходит |
|---|---|
| «настрой trio-sync здесь» / этот файл | Создаёт `.trio/` на новом проекте (этот процесс) |
| «какой статус» / «догони меня» | Любая поверхность читает `STATUS.md` + последние `LEDGER.md` и коротко пересказывает |
| «передай Code: <текст>» | Вопрос уходит в `TO_CODE.md` |
| «что ответил Code» | Чтение `FROM_CODE.md` и пересказ |
| «залогируй это» | Принудительная запись в `LEDGER.md`/`STATUS.md` сейчас |
