# Переход trio-sync v0.4.x → duo-sync v0.5.0

Два раздела: **инвентаризация** (куда делась каждая часть старого протокола — чтобы убедиться, что ничего не потеряно) и **процедура переноса проекта**.

## 1. Инвентаризация: старое → новое

Каждая строка — правило, файл или урок из v0.4.1. «Сохранено» значит, что оно есть в новом протоколе; «Убрано» — только с причиной.

## 2. Процедура переноса проекта

Выполняет Claude (с доступом к папке) или Code. Не делай этого, пока в проекте идёт активная сессия, пишущая в `.trio/` (проверь время изменения файлов; при сомнении спроси пользователя).

1. **Снимок.** Создай `.trio/_legacy-v0.4/` и скопируй туда `STATUS.md`, `TO_CODE.md`, `FROM_CODE.md` (и `CHAT_LINKS.md`, если есть). Запиши в `_legacy-v0.4/MANIFEST.txt` sha256 и размер каждого скопированного файла **и** файлов `LEDGER.md`, `DIALOGUE.md`, `DIALOGUE-archive-*.md`, которые не копируются (чтобы потом сверить, что они не изменились, кроме разрешённой дописки в LEDGER).
2. **STATE.md.** Собери из `STATUS.md`: Current focus → `Фокус`; Recent decisions → `Решения` (все, дословно); Open questions → `Открыто` (все); Next actions: невыполненные → `Дальше`, выполненные → `Сделано`; Standing requirements → `Постоянные требования`. `ПРОШЛАЯ` и `ПОЗАПРОШЛАЯ` — «(пусто)». Если в `STATUS.md` есть что-то, чему не нашлось поля, — положи в `Постоянные требования` или в конец `СЕЙЧАС` как «Прочее», но не выбрасывай.
3. **INBOX.md.** Из `TO_CODE.md` и `FROM_CODE.md` перенеси **каждую** запись, которая ещё не перенесена в `DIALOGUE.md` (то есть реально открытую), как элемент инбокса — текст дословно. Если запись в инбоксе явно устарела или закрыта, а в `DIALOGUE.md` её нет, — не выбрасывай и не угадывай: перенеси как есть и пометь «проверить актуальность». Пустые файлы дают пустой `Открыто`.
4. **LEDGER.md и DIALOGUE.md** не трогай, кроме одной дописанной сверху строки в `LEDGER.md`: `_Начиная с <дата> формат: блоки вытесняются сюда из STATE.md (duo-sync v0.5.0). Записи ниже — прежний формат; Chat/Cowork читать как Claude._`
5. **CLAUDE.md проекта.** Замени блок про trio-sync блоком из `NEW_PROJECT.md` (шаг 6). Если `CLAUDE.md` ссылается на `TO_CODE.md` как на «бриф» (как у Taskinator), замени ссылку на `INBOX.md` и убедись, что смысл «свежий бриф» сохранён.
6. **Старые файлы.** Файлы `STATUS.md`, `TO_CODE.md`, `FROM_CODE.md`, `CHAT_LINKS.md` замени заглушкой в одну строку: `Устарело в duo-sync v0.5.0 — см. STATE.md / INBOX.md. Копия: _legacy-v0.4/. Файл можно удалить.` Удалить сами файлы может Code (`git rm`) или пользователь.
7. **Проверка** (все пункты, по порядку):
   - число открытых пунктов в старых `TO_CODE.md`/`FROM_CODE.md` = числу элементов в `Открыто` нового `INBOX.md`;
   - каждый пункт из `Open questions`, `Next actions` (невыполненные) и `Standing requirements` старого `STATUS.md` найден в `STATE.md` — сверка построчно, не по памяти;
   - sha256 `_legacy-v0.4/*` совпадает со значениями в `MANIFEST.txt` и с исходниками до замены на заглушки;
   - sha256 `DIALOGUE.md`, `DIALOGUE-archive-*.md` не изменились; `LEDGER.md` отличается от исходного только одной дописанной сверху строкой;
   - в `.gitignore` проекта ничего не изменилось (у Finanon `.trio/` в нём намеренно).
8. **Записи о переносе.** В `СЕЙЧАС` добавь `Сделано: перенесено на duo-sync v0.5.0 (снимок в _legacy-v0.4/)`.
9. **Через неделю** (или когда пользователь подтвердит, что всё работает) — удалить заглушки и по желанию `_legacy-v0.4/`.

### Особые случаи

- **Finanon:** `.trio/` в `.gitignore` намеренно, живёт только на диске, переезжает между машинами скриптом `claude-workspace/sync-state.ps1` как снимок `state/finanon/trio/`. После переноса нужно один раз обновить снимок (`sync-state.ps1`), иначе на второй машине останется v0.4.
- **Taskinator:** `.trio/` в git, `CLAUDE.md` делает `TO_CODE.md` главным «брифом», файлы очень большие (`FROM_CODE.md` ≈ 220 КБ, `TO_CODE.md` ≈ 65 КБ, `STATUS.md` ≈ 44 КБ), проект активный. Перенос — только в «тихий» момент и вместе с пользователем: большие `TO_CODE.md`/`FROM_CODE.md` содержат накопленные брифы, которые нельзя ни потерять, ни разобрать на глаз. Исходники не меняются, пока не готов и не проверен `INBOX.md`.
- **trio-sync (этот репозиторий):** протокол лежит в корне, без вложенной `.trio/`; шаги те же, `_legacy-v0.4/` не нужен — старые версии лежат в `docs/archive/v0.4.1/` и в git.

## 3. Claude Project «Cloude Trio»

Зеркала `claude/trio-status-snapshot.md`, `trio-from-code-snapshot.md`, `trio-dialogue-mirror.md`, `trio-chat-links.md` больше не нужны. Перед удалением сверить: нет ли в зеркале дословного текста, которого нет в `DIALOGUE.md` репозитория. Удалять только после сверки и с согласия пользователя. Synced source (GitHub `Myrshefor/.trio`) остаётся — он даёт приложению чтение репозитория.

## 4. Установка

1. Установить плагин duo-sync v0.5.0 (Cowork: файл `.plugin`; Claude Code: `/plugin marketplace add "<путь к .trio\plugin\>"`, `/plugin install duo-sync@duo-sync-marketplace`, `/reload-plugins`).
2. Отключить/удалить `trio-sync` и `trio-sync-2`, чтобы не срабатывали оба.
3. Обновить в проектах блок в `CLAUDE.md` (процедура шаг 5).
