# duo-sync — сценарии обмена (v0.5.0)

Каноническое описание «кто с кем как говорит». В trio-sync их было шесть, потому что Chat не мог писать файлы и шёл через пользователя. Теперь поверхностей две — **Claude** и **Code** — и обе пишут в `.trio/` напрямую. Прежняя версия (шесть сценариев + матрица) сохранена в `docs/archive/v0.4.1/scenarios.md`.

## Один канал

Всё между Claude и Code идёт через `.trio/`:

- что происходит и что решено — `STATE.md`;
- «сделай / ответь / посмотри» одной стороне другой — `INBOX.md`;
- дословная история закрытого — `DIALOGUE.md`.

Пользователь не мост, а участник: он может поручить, ответить, передать текст куда угодно, но протокол не зависит от этого.

## Сценарии

### 1. Claude → Code (задача, вопрос)
Claude добавляет элемент в `INBOX.md` (`Claude → Code`, `open`), указывает файлы и ожидаемый результат. Code при старте читает `INBOX.md`, делает, пишет `Ответ`, ставит `answered`, отражает работу в `СЕЙЧАС`. Claude читает ответ и закрывает.

### 2. Code → Claude (находка, вопрос к планированию или оценке)
Зеркально: элемент `Code → Claude`. Если решения не требуется и это просто факт («сделано, коммит abc123») — достаточно записи в `СЕЙЧАС`, инбокс не нужен.

### 3. Claude ↔ Claude (две сессии приложения, в том числе при смене устройства)
Сессии друг друга не видят. Окончание сессии = обновлённый `СЕЙЧАС`. Начало = чтение `STATE.md` и `INBOX.md`. Адресата `Claude → Claude` использовать для «отложенных» напоминаний себе же на другую сессию.

### 4. Code ↔ Code
То же самое: другая сессия Code не помнит предыдущую.

### 5. Пользователь передаёт что-то вручную
Допустимо (вставил текст в другую сессию, устно переспросил), но не заменяет запись. Решение, принятое в разговоре и не записанное в `.trio/`, для другой стороны не существует.

### 6. Граница: `INBOX.md` и собственные возможности Claude
Если Claude может закрыть вопрос сам — через device-bridge, подключённый репозиторий, веб, планировщик — он делает это сам и не заводит круг через Code «для отметки в протоколе». `INBOX.md` — для того, что может сделать или решить только другая поверхность (запуск, коммит, проверка в терминале; решение по плану, обзор), и для работы, которая должна пережить границу сессий.

### 7. Нет доступа к файлам (Project без подключённого репозитория и без связи с компьютером)
Claude честно говорит, что `.trio/` не видит, просит приложить `STATE.md` и `INBOX.md` и не выдумывает их содержимое. Если нужно сохранить результат — отдаёт текст пользователю, чтобы тот положил его в `INBOX.md`/`STATE.md`.

## Матрица

| Откуда → куда | Канал | Автоматически |
|---|---|---|
| Claude → Code | `INBOX.md` | да |
| Code → Claude | `INBOX.md` / `STATE.md` | да |
| Claude → Claude | `STATE.md` / `INBOX.md` | да |
| Code → Code | `STATE.md` / `INBOX.md` | да |

Все четыре направления прямые. Раньше автоматическим было только Cowork ↔ Code.
